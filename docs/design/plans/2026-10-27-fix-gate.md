# Fix Gate Implementation Plan

**Goal:** A fix becomes a point only if its accuracy is at most 50 m and it is not a jump from the
last point of its segment; two agreeing GNSS-grade fixes re-anchor a wrong anchor.

**Design:** `docs/design/specs/2026-10-27-fix-gate-design.md` — read it first; this plan does not
repeat its reasoning.

**Tech Stack:** React Native (Expo SDK 57), TypeScript (strict), Jest (jest-expo).

## Global Constraints

- **Pure logic is TDD'd** — tests first, asserting numbers.
- **Seams:** `expo-location` stays in `src/location/`; SQL stays in `src/data/db/`. Recording uses
  the port type `LocationFix` and the `ActivitiesRepository` interface.
- **No change-narrating comments.** Comment only the non-obvious *why*.
- **Gate:** `npm run verify` (from the main checkout; inside a worktree run
  `./node_modules/.bin/jest --testPathIgnorePatterns=/node_modules/` and check the new test files
  appear in the run).
- **Commits:** Conventional Commits, lowercase, scoped. Never commit `node_modules` or `.env`.

### T1 — unknown accuracy is `null` at the port

**Blocked by:** none.

  `undefined` to `null`; a positive accuracy passes through unchanged.

- Tests in `src/location/__tests__/expoLocation.test.ts`: `0 → null`, `-1 → null`, `null → null`,
  `12.5 → 12.5`.

### T3 — `gateFixes`, the pure gate

**Blocked by:** none.

`src/recording/fixGate.ts`, tests in `src/recording/__tests__/fixGate.test.ts`, written first.

```ts
export const MAX_ACCURACY_M = 50
export const MAX_SPEED_MPS = 10
export const JUMP_FLOOR_M = 50
export const RECOVERY_ACCURACY_M = 20

export interface Anchor { lat: number; lng: number; t: number }
export interface RejectedJump { metres: number; allowedMetres: number; seconds: number }
export interface GateResult {
  kept: LocationFix[]
  candidate: LocationFix | null
  droppedAccuracy: number
  droppedJump: number
  recovered: number
  worstRejectedAccuracy: number | null
  worstJump: RejectedJump | null
}

export function gateFixes(fixes: LocationFix[], anchor: Anchor | null, candidate: LocationFix | null): GateResult
```

For each fix in order (`t` in ms; `seconds = (fix.t − from.t) / 1000`;
`plausible(from, fix)` ⇔ `seconds > 0 && haversine ≤ MAX_SPEED_MPS × seconds + JUMP_FLOOR_M`;
`votes(fix)` ⇔ `fix.accuracy !== null && fix.accuracy ≤ RECOVERY_ACCURACY_M`):

1. `accuracy !== null && accuracy > MAX_ACCURACY_M` → `droppedAccuracy++`, track
   `worstRejectedAccuracy`; the candidate is untouched.
2. else no anchor, or `plausible(anchor, fix)` → kept; anchor = fix; candidate = null.
3. else `candidate && votes(fix) && plausible(candidate, fix)` → kept, `recovered++`; anchor = fix;
   candidate = null.
4. else → `droppedJump++`, track `worstJump` (largest `metres − allowedMetres`); if `votes(fix)` the
   candidate becomes this fix, otherwise it is untouched.

Tests (numbers, not structure):
- empty input → nothing kept, candidate passed through, counts 0, worsts null;
- accuracy 50 kept, 50.1 dropped; `null` accuracy kept; worstRejectedAccuracy is the max;
- **the 2026-10-26 sequence** — anchor 3.5 m; then 383 m @ +5 s 675 m away, 390 m @ +10 s same
  place, 34 m @ +16 s back at the anchor: the two coarse fixes dropped for accuracy, the last kept,
  nothing recovered;
- the same sequence with the coarse fixes at 45 m accuracy (a wifi cluster): both dropped as jumps,
  neither becomes the candidate, nothing recovered;
- no anchor → first fix kept on rule 1 alone;
- 15 m at +1 s kept; 120 m at +15 s kept; 200 m at +15 s kept (boundary), 201 m dropped;
- `Δt = 0` and `Δt < 0` dropped as jumps;
- fold: A, then B 30 m on at +5 s, then C 30 m past B at +10 s → all kept, C judged from B;
- recovery: anchor wrong by 600 m; fix 1 (8 m accuracy) dropped and becomes candidate; fix 2 (8 m,
  10 m from fix 1, +5 s) kept, recovered = 1; fix 3 judged from fix 2;
- recovery across calls: candidate returned by one call and passed into the next;
- a lone outlier (8 m accuracy) then a fix near the anchor → outlier dropped, the next kept, candidate
  null;
- a non-voting jump (30 m accuracy) leaves an existing candidate in place;
- worstJump reports metres, allowedMetres, seconds of the largest excess.

### T4 — wire the gate into capture, log it

**Blocked by:** T1, T2, T3.

- `src/recording/locationTask.ts`: the handler body runs through one module-level
  `createSerialQueue()` (`src/async/serialQueue.ts`). Per delivery: session and paused check as
  today → `fixesInSegment` → anchor = `getLastSegmentPoint(session.id, session.currentSegment)` →
  candidate = the module-held one if its `(sessionId, segment)` tag matches, else null →
  `gateFixes` → store the returned candidate with the current tag → log → append `kept` to the
  repository and the store (nothing when empty). The existing read of `livePoints` for the previous
  point goes away.
- `fixBatchSummary` (moved from `src/log/` to `src/recording/` at review): signature `(arrived, inSegment, gate: GateResult, anchor: Anchor |
  null)`; emits `arrived`, `kept`, `droppedBeforeSegment`, `droppedAccuracy`, `droppedJump`,
  `recovered`, `firstAt`, `lastAt`, `bestAccuracy`, `worstRejectedAccuracy`, `worstJump`,
  `metresFromAnchor` (anchor → first in-segment fix, whole metres). Still no coordinate.
- Tests: `fixBatchSummary.test.ts` (new fields; no lat/lng anywhere in the
  output), `src/recording/__tests__/locationTask.test.ts` (only kept fixes appended; an all-rejected
  delivery appends nothing and still logs; anchor taken from the repository for the current segment;
  candidate carried across two deliveries of one segment and dropped across a segment change; two
  overlapping deliveries run one after the other).
- `docs/architecture/debug-log.md`: document the `fix batch` fields.
